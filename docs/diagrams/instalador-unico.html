DevAgentKit · propuesta de instalación

Un comando.
Un menú.
Todo instalado.

El compañero no aprende flags: ejecuta una línea, elige su perfil y el instalador deja el kit, las skills, los guardarraíles, CodeGraph, Engram y tech-doc en su repo de desarrollo.

una línea perfiles dinámicos CodeGraph + Engram tech-doc privado sin producción

La experiencia

lo que ve el compañero
# clonar el kit y ejecutar el instalador git clone https://github.com/ScalpersCompany/dev-agent-kit.git "$HOME/.dev-agent-kit" \ && "$HOME/.dev-agent-kit/install.sh"

No se usa curl | bash: el compañero puede leer el script antes de ejecutarlo. Si ya tiene el kit, ejecuta ./install.sh.

El flujo

seis etapas, una sola decisión
0

Preflight

bash, git, python, rsync, repo destino y accesos.

1

Preguntas

perfil, perfil activo, agentes, CodeGraph, Engram y tech-doc.

2

Instala

kit, perfiles, todas las skills, comandos y adaptadores.

3

Protege

hooks, guard, verify, comment_lint y exclusiones locales.

4

Indexa y recuerda

CodeGraph sobre el repo; Engram guarda la instalación.

5

Doctor

qué quedó instalado, qué es opcional y qué se omitió.

El menú de perfiles

se genera del repo, no está hardcodeado

[S/n] ¿Engram? [S/n] ¿Tech-doc? [S/n] (privado) ¿Construir HTML? [s/N]

La regla

  • Un perfil, otro o todos.
  • Si instalas varios, eliges uno activo.
  • Un perfil nuevo aparece sin tocar el instalador.
  • Si no hay acceso a tech-doc, el resto sigue.
  • Las opciones se pueden fijar con flags para automatización.

Qué deja instalado

“todo” significa todo lo repetible

En el repo

  • AGENTS.md, skills, commands y agents.
  • Perfil(es) en .dev-agent/profiles/ y perfil activo.
  • Hooks pre-commit y pre-push.
  • guard, verify, comment_lint y verify/config.env.
  • CodeGraph indexado y .engram/config.json.
  • docs/TECHDOC.md y enlace local docs/techdoc.html.

En los agentes

  • Claude Code y OpenCode: adaptadores generados.
  • Codex, pi y Hermes: skills copiadas o gentle-ai sync.
  • Todos los comandos que el host soporte.
  • Ninguna clave ni token en el repo.
  • Un wrapper dev-agent para no recordar rutas.

Uso diario

lo que se enseña después de instalar
ComandoPara qué
dev-agent doctorSaber qué está instalado, qué falta y qué es opcional.
dev-agent guardPasar las comprobaciones deterministas antes del commit.
dev-agent verifyEjecutar el comportamiento real y dejar evidencia.
dev-agent reviewRevisar un diff con la skill y un veredicto.
dev-agent eval --dry-runValidar un caso de skill sin gastar modelo.
dev-agent profile use odoo11Cambiar el perfil activo del repo.
dev-agent codegraph syncReindexar después de cambios grandes.
dev-agent memory save ...Guardar una decisión o un bug en Engram.

Mejorar una skill

sin convertir la mejora en una puerta
corrección repetida→correct→editar SKILL.md→caso de eval→--dry-run→K=3→docs

La skill cambia cuando el mecanismo cambia: lint, test, CI o regla. La media sola no basta; se mira la dispersión. Una skill inestable no se declara verde.

Límites

lo que el instalador no hace
no toca producción no guarda secretos no hace push no borra sin backup no copia el HTML privado no instala un modelo no aprobado

Criterios de aceptación

verde antes de dar el visto bueno
  • Una línea y termina instalado.
  • Menú real de perfiles y perfil activo.
  • Todas las skills y guardarraíles.
  • CodeGraph y Engram si están.
  • Tech-doc enlazado; HTML local.
  • Doctor distingue omitido de verde.
  • Instalador idempotente y probado.
  • Sin secretos, producción ni push.
Para el visto bueno

Cinco decisiones, una sola aprobación.

  1. install.sh como entrada única; bin/dev-agent como wrapper de uso.
  2. Menú dinámico de perfiles, opción “todos” y elección de perfil activo.
  3. CodeGraph y Engram activados si están instalados; omitidos con aviso si no.
  4. Tech-doc opcional; HTML solo con --build-techdoc-html; nunca copiado.
  5. Tres guías rápidas: instalador, uso diario y mejora de skills.

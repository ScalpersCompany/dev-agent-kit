El problema

No es que el agente escriba. Es que no sabemos qué ha comprobado.

01por qué existe
01

Cada agente, un flujo

Claude, OpenCode, Codex, pi y Hermes tienen sus propias reglas. El mismo cambio se comporta distinto según quién lo haya hecho.

02

“Hecho” sin evidencia

Una respuesta convincente no es una prueba. Sin salida de test, HTTP o artefacto, la revisión empieza de cero.

03

Contexto que se pierde

La decisión vive en el chat. Al cerrar la sesión, el repo no sabe por qué se eligió una solución.

El coste: más tiempo revisando, más dudas y más cambios que parecen terminados sin estarlo.

DevAgentKit02 · La idea
Marco

Qué es y qué no es.

03expectativas

Es

Una puerta local de calidad. Un contrato de perfiles. Un conjunto de skills. Un instalador. Una forma de conservar contexto y normas.

No es

Ni un modelo, ni un CI remoto, ni un auto-merge, ni un despliegue, ni un repo de producto fijo. No sustituye la revisión humana.

La distinción: hecho ≠ verificado ≠ aprobado. El kit hace visible la diferencia.

DevAgentKit04 · Arquitectura
Autoinstalación

Se instala con una línea y un menú.

05puesta en marcha
git clone https://github.com/ScalpersCompany/dev-agent-kit.git "$HOME/.dev-agent-kit" \ && "$HOME/.dev-agent-kit/install.sh"

Perfil

El instalador descubre los perfiles del repo y pregunta cuál o cuáles instalar; siempre queda uno activo.

Agentes

Claude, OpenCode, Codex, pi, Hermes o todos. Las skills se copian a la ruta que cada uno usa.

Extras

CodeGraph, Engram y tech-doc. Si faltan o no hay acceso, avisa y el núcleo sigue instalado.

No hay que memorizar flags: la instalación normal es interactiva. La versión sin preguntas existe para automatización.

DevAgentKit09 · Skills
Contexto y norma

Que el repo y la decisión no vivan solo en el chat.

10memoria

CodeGraph

Indexa estructura, símbolos y llamadas. El agente consulta el mapa en vez de adivinar por el árbol.

Engram

Guarda decisiones, bugs y contexto del proyecto. La sesión termina; la memoria no.

tech-doc

La norma de empresa se enlaza en ~/.agents/AGENTS.md. Si el clon está sucio, el check falla cerrado.

CodeGraph y Engram son apoyo, no puertas. tech-doc es la fuente canónica; el kit no la copia ni la reemplaza.

DevAgentKit11 · Ciclo de trabajo
Límites

Lo que el sistema no hace.

12confianza

No toca producción

Se instala en la base de desarrollo; no despliega ni configura servidores.

No guarda secretos

Las claves viven en el entorno del agente, nunca en el repo o la evidencia.

No hace push

El push, el merge y el release siguen siendo decisiones humanas.

No borra

Respalda con .bak-<fecha> antes de reemplazar. No toca datos ni historial.

El CI de Scalpers no se toca. La puerta local es una ayuda; el CI y la revisión humana son la garantía dura.
